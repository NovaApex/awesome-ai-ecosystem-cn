fast-jev-compaction · tamaratran/fast-jev-compaction — Claude Code 插件：用 TypeSafe Jev 打分替代压缩摘要，只删过期工具调用、保留内容一字不改
  • 相关链接：npm 包 fast-jev-compaction
  • 定位：Claude Code 插件 + npm 库，用 Jev 决策替换 Claude Code 内建的压缩摘要。要解决的痛点：让 LLM"总结"旧对话是有损的 —— 一个文件路径、一段精确报错、一条约束或一条命令，都可能在以后要紧时消失。这个库从不改写任何内容：只删掉 Jev 判定"不再需要"的工具调用与工具结果，判断时把整段对话喂给 Jev；用户与助手的文字逐字保留、顺序不变。仓库同时是 npm 包（src/）与 Claude Code 插件（hooks/、.claude-plugin/）。
  • 工作机制（7 步）：
    1. 每个 tool_use 按 tool_use_id 与其 tool_result 配对；首条消息与最新 preserveRecentMessages 条被钉住，永不触碰。
    2. 送给 Jev 的 state = 目前整段对话（从旧到新），其中每个工具结果被换成一行短注（ok, 4213 chars (omitted)）；工具输入与文本都保留，不做任何总结。
    3. state 按 maxStateTokens（默认 25k） 分级压缩，前一级不够才上下一级：工具输入截到 1000 → 200 → 60 字符；长文本缩成"头 + 尾"（从最旧的非钉住消息开始）；旧的非钉住消息折叠成 [… N chars omitted …]；旧的工具调用压成一行（t12 Read file_path=src/a.ts → ok 480ch）；旧的纯调用消息直接剔除；连续的纯调用消息折成一条。仍放不下就抛错。token 数为无分词器估算（每 6 个字母算 1 词、每个数字 0.5 token、其它符号约 1 token），刻意校准到略高于 Jev 自报的数。
    4. 对每个非钉住调用，Jev 回答两个 noul 问题：这个调用要不要留（"知道做过它"、连同输入，还有意义吗）、这个结果要不要逐字留（内容还需要，且重跑工具也拿不回来）。
    5. 问题按 maxRequestTokens（默认 30k，压在 Jev 的 32k 请求上限之下） 拆成多批，每批都重发同一份完整 state，并发执行后合并答案。
    6. 逐调用按 keepThreshold（默认 0.5） 决策：keepResult ≥ 阈值 → 调用与结果都留；否则 keepCall ≥ 阈值 → 只留调用，把结果截到前 truncateHeadChars 字符 + 一行注；都不达标 → 调用与结果一起删。
    7. 重建消息列表：内容全丢的消息被移除，未触碰的消息以同一对象返回，绝不出现只有结果没有调用的状态。
    • 出错策略：Jev 失败、答案格式错误、缺 key、历史塞不下 —— 一律抛错，由调用方（或 Claude Code hook）决定回退。

  • 动作空间：每次观察生成一张带编号的元素表（形如 [2] combobox Where from? · San Francisco）；可选操作只有 CLICK / TYPE_TEXT / SELECT / SCROLL_UP / SCROLL_DOWN / WAIT / DONE / BLOCKED，且只提供页面上真实存在的操作与目标。操作头与目标头共享同一次观察，所以"两个决策 = 一次网络往返"；目标问题是投机式的（操作是 CLICK 时只有 click_target 能执行），每个目标头只含兼容元素，原生下拉选项带观察到的元素/选项索引。没有站点专用动作脚本，也没有预制字段字符串——Flights 示例只给目标，再由独立检查验证结果；截图渲染器是事后加标签，不驱动浏览器。
  • 为什么快（工程要点）：
    • 一个决策周期只发一次请求
    • 默认循环不用截图（Jev 吃结构化状态，截图只给 inspector 与录像用）
    • 每次快照只一次浏览器调用，原子读出可见控件及其名称/值/文本并保留真实 DOM 节点引用
    • 校验选中目标（点击前检查 document、表单值、目标与邻近上下文，解析当前几何，拒绝被遮挡控件，动画本身不触发重新预测）
    • 等有用状态（combobox 输入后等可见建议，上限 200ms；其它交互最多两帧或 50ms；这些读取发生在执行被记录之后）
    • 保持隐藏标签页渲染（焦点模拟避免后台动画节流，且不切换 Chrome 可见标签）
    • 只发可见文本（离屏正文与页脚不进模型上下文）
    • 复用被打断的文本请求（整份文本助手输入未变才复用已生成的值）
  • 安全设计：模型输出永不变成选择器、坐标、shell 命令或可执行 JS；每个被执行的目标都从观察到的节点解析，执行器会重查页面新鲜度与点击遮挡；文本助手的输出必须先解析成一个小 JSON 对象才能输入。
